# Enhanced Web Security Analysis Using Custom Nmap NSE Scripts

Custom Nmap Scripting Engine (NSE) scripts developed for basic web security analysis as part of the Cyber Security course at the School of Computer Science and Engineering (SCOPE), Vellore Institute of Technology, Chennai.

## Overview

This repository contains two custom Nmap NSE scripts designed to automate selected web security checks on HTTP services.

1. **Admin Panel Finder:** Checks common administrative and login paths and reports potential findings based on HTTP responses and page content.
2. **HTTP Security Headers Checker:** Checks for the presence of six commonly used HTTP security headers and generates a simple percentage score.

These scripts demonstrate how the Nmap Scripting Engine and Lua can be used to extend Nmap's functionality for educational security testing.

## Project Objectives

- Develop custom Nmap NSE scripts for web security analysis.
- Identify potential exposure of common administrative paths.
- Check the presence of important HTTP security headers.
- Automate selected checks and present readable results.
- Gain practical experience with Nmap, Lua scripting, and HTTP responses.

## Script 1: Admin Panel Finder

### Objective

The Admin Panel Finder checks a predefined list of common administrative and login paths on an HTTP service. It examines HTTP status codes and selected page content to identify potential administrative interfaces.

### Paths Checked

- `/admin`
- `/login`
- `/administrator`
- `/admin/login`
- `/dashboard`
- `/wp-admin`
- `/phpmyadmin`
- `/cpanel`
- `/adminpanel`
- `/backend`

### Features

- Checks predefined administrative and login paths.
- Reports selected HTTP 401 responses as protected paths.
- Reports selected HTTP 403 responses as forbidden paths.
- Validates page content for selected HTTP 200 responses.
- Displays a count of detected paths and a basic exposure indicator.

### Usage

Run the script against a system you own or have explicit permission to test:

```bash
nmap -sV -p 8080 --script ./admin-panel-finder.nse 127.0.0.1
```

## Script 2: HTTP Security Headers Checker

### Objective

The HTTP Security Headers Checker retrieves the HTTP response from the root path (`/`) and checks whether selected security headers are present.

### Security Headers Checked

1. Content-Security-Policy
2. Strict-Transport-Security
3. X-Frame-Options
4. X-Content-Type-Options
5. Referrer-Policy
6. Permissions-Policy

### Features

- Retrieves HTTP response headers.
- Normalizes header names for case-insensitive lookup.
- Reports each selected header as found or missing.
- Displays returned header values when available.
- Calculates a percentage based on the number of checked headers found.
- Displays a basic security-configuration summary.

### Usage

```bash
nmap -sV -p 8080 --script ./http-security-headers.nse 127.0.0.1
```

## Testing Environment

The scripts can be tested in a controlled local environment using a Python HTTP server.

Start the server in one terminal:

```bash
python3 -m http.server 8080 --bind 127.0.0.1
```

Open another terminal and navigate to the directory containing the scripts. Run the appropriate Nmap command against the local service.

For the HTTP Security Headers Checker, save the output using:

```bash
nmap -sV -p 8080 --script ./http-security-headers.nse 127.0.0.1 -oN http-security-headers-output.txt
```

The Python server is a basic test target. It may not provide realistic administrative interfaces or security headers, so the output should be interpreted in that context.

## Limitations

- The Admin Panel Finder checks only a predefined list of paths.
- A status code or matching keyword does not conclusively prove that a page is an administrative interface.
- The HTTP Security Headers Checker examines only the root path.
- Header presence alone does not confirm that the header is configured correctly.
- The percentage score is a simplified indicator based on six selected headers, not a complete security assessment.
- Results may vary depending on the server, configuration, and HTTP responses.
